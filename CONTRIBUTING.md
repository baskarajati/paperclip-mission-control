# Contributing

## Current phase

The project is in architecture planning. Implementation pull requests are premature until an approved plan exists under `docs/plans/`.

## Change requirements

- Keep changes scoped to one milestone or defect.
- Link the governing plan, decision, or public issue.
- Include tests for behavior changes.
- Preserve Paperclip governance and checkout boundaries.
- Document compatibility impact and rollback behavior.
- Do not combine unrelated Paperclip core fixes with Mission Control work.

## Pull requests

Include:

- Problem and intended outcome
- Plan or decision reference
- Compatibility impact
- Verification performed
- Failure and rollback behavior
- Model and tools used

## Security

Report vulnerabilities through GitHub private vulnerability reporting. Do not open public issues for undisclosed security problems.
