# Paperclip Mission Control

Reusable mission-to-phase continuity for self-hosted Paperclip companies.

## Status

Pre-alpha architecture work. The repository contains no installable plugin yet.

Implementation starts only after:

1. The architecture and milestone plan are written.
2. Claude Opus 5 and Ox Alpha independently review the plan.
3. Review findings are reconciled against the Paperclip repository.
4. The project owner approves implementation.

## Intended scope

- Reconcile company missions, phases, projects, and execution issues.
- Propose evidence-backed phase transitions.
- Require explicit confirmation at configured governance boundaries.
- Use supported Paperclip plugin, routine, issue, document, and interaction APIs.
- Detect incompatible Paperclip versions and fail closed.

## Non-goals

- Forking or monkey-patching Paperclip.
- Replacing Paperclip scheduling, approvals, budgets, checkout ownership, or recovery.
- Repairing unrelated adapters, credentials, sandbox networking, or model discovery.
- Supporting Paperclip Cloud before the plugin runtime supports distributed installation.
